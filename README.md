# RailFlow Backend — Railway Disruption & Platform Conflict Simulator

Backend for **RailFlow: Railway Disruption & Platform Conflict Simulator** developed for **VORTEXA 3.0**.

Built with **Python**, **FastAPI**, **Pydantic v2**, and **pytest**. Adheres strictly to [`docs/api-contract.md`](docs/api-contract.md).

---

## Key Features & Constraints

1. **Independent Validation**:
   - `app/validator.py` operates completely independently without importing or reusing `app/solver.py`.
   - Validates duplicate/unknown IDs, negative or inverted intervals (`arrival >= departure`), platform closures, overlaps, and minimum gap violations.
   - Every candidate schedule generated by the solver is validated before returning.

2. **Deterministic Constraint-Based Solver**:
   - Uses greedy assignment with branch-and-bound backtracking.
   - Enforces zero platform overlaps, required minimum headway gaps (`minimum_gap_minutes`), and closure intervals.
   - Preserves original platforms for unaffected trains whenever feasible.
   - Records descriptive changelog reasons for every delay or reassignment.
   - Returns explicit `status: "no_solution"` if constraints cannot be satisfied.

3. **Free-Text Disruption Parser**:
   - Parses complex queries like `"Train T12 delayed 20 min. Platform P2 closed 10:00-11:00"` using regex and `dateparser`.
   - Converts all times into minutes after midnight.
   - Generates warnings for ambiguous or unrecognized text without silently guessing.

## Implemented API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/health` | Health check and version status |
| `GET` | `/api/timetable` | Returns default fictional station and active timetable |
| `POST` | `/api/validate` | Independently validates a provided timetable |
| `POST` | `/api/disruptions/parse` | Parses free-text disruption reports |
| `POST` | `/api/disruptions/apply` | Replans timetable with solver and runs validation |

## Setup & Running

### 1. Requirements
- Python 3.10+ (tested on Python 3.13)
- `pip`

### 2. Install Dependencies
```bash
pip install -r requirements.txt
```

### 3. Run Development Server
```bash
uvicorn app.main:app --reload --port 8000
```
Interactive Swagger docs: [http://localhost:8000/docs](http://localhost:8000/docs)  
Health check: [http://localhost:8000/api/health](http://localhost:8000/api/health)

CORS is enabled by default for Vite (`http://localhost:5173`) and can be overridden via the `CORS_ORIGINS` environment variable.

### 4. Run Automated Tests
```bash
python -m pytest -v
```
All 36 unit and integration test cases run in ~5-6 seconds.

## Frontend Setup & Running

The frontend dashboard is built with React, Vite, and CSS.

### 1. Install Frontend Dependencies
```bash
cd frontend
npm install
```

### 2. Run Frontend Development Server
```bash
npm run dev
```
Open [http://localhost:5173](http://localhost:5173) in your browser.

### 3. Build for Production
```bash
npm run build
```
The application will bundle into `frontend/dist/`.
